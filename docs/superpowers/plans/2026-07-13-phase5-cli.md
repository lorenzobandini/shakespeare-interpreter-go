## Step 5.4: `repl` Subcommand — Replay-based Accumulating Buffer Model

This is the most complex step. It implements the Replay-based Accumulating Buffer REPL. All state management is self-contained in the `replCmd.RunE` closure — no changes to `internal/runtime/` or `internal/parser/`.

### Architecture Overview

```
┌──────────────────────┐
│    REPL struct       │  holds all state: buffer, recordings,
│                      │  checkpoints, stdout capture
├──────────────────────┤
│ replLoop()           │  main readline loop
│ accumulateBlock()    │  read multi-line SPL block
│ runPipeline()        │  lex → parse → analyze → execute
│ checkpoint / restore │  buffer + input-cursor rollback
│ makeSkeleton()       │  synthetic Title/Act I/Scene I
│ declareCharacters()  │  auto-declaration scanner
│ recordedReader()     │  replay stdin implementation
│ sliceOutput()        │  compute delta display
└──────────────────────┘
```

### 5.4.1: Create `replCmd` skeleton

- **Goal**: Define the Cobra command entry point.
- **Context Files**: `cmd/shpl/main.go`
- **Implementation Details**:
  - `replCmd`: `Use: "repl"`, `Short: "Start an interactive SPL REPL"`, `Args: cobra.NoArgs`, `RunE` is the REPL entry point.
  - The `RunE` captures `cmd.OutOrStdout()` (output writer), `os.Stdin` (input reader), and calls a `replLoop()` function.
  - Use a struct to hold REPL state:
    - `buffer bytes.Buffer` — accumulated SPL source text
    - `recordedInputs []byte` — recorded stdin bytes for replay
    - `recordedCursor int` — cursor within recordedInputs
    - `lastOutputLen int` — length of last successful run stdout (for slicing)
    - `declaredChars map[string]bool` — characters already declared
    - `skeletonBuilt bool` — whether skeleton has been prepended
  - Note: this struct is local to the `replCmd.RunE` closure, not exported.

### 5.4.2: Implement the REPL input loop

- **Goal**: Main loop: print `spl>` prompt, read lines, accumulate blocks, trigger replay on blank line.
- **Implementation Details**: Algorithm:
  1. Print `spl> ` prompt to `os.Stderr`.
  2. Use `bufio.NewScanner(os.Stdin)` to read lines.
  3. Accumulate lines into a per-block buffer.
  4. When a blank line (empty after trim) is encountered:
     - If the block buffer is empty, continue (just another blank line).
     - If the block buffer is non-empty, submit the block for replay.
     - After successful replay, reset the block buffer.
  5. If `scanner.Err()` (e.g., EOF), exit the loop gracefully.
  6. Before each `Scan()`, print the prompt again.
- **Prompt semantics**: First prompt for a new block is `spl> `. Continuation prompts (while reading multi-line input) are `...> `.

### 5.4.3: Handle Ctrl+C (SIGINT) and Ctrl+D (EOF)

- **Goal**: Graceful exit on interrupt/EOF.
- **Implementation Details**:
  - Set up a `os.Signal` channel for `os.Interrupt` (`SIGINT`). In a separate goroutine, trap the first `SIGINT`:
    - Print `^C\n` to stderr, return from `replLoop`.
  - For Ctrl+D: `scanner.Scan()` returns false, `scanner.Err()` is nil. Detect this and break the loop.
  - `main()`'s existing error handler will print nothing (nil error), and the process exits cleanly.

### 5.4.4: Implement REPL-specific commands

- **Goal**: Lines starting with `:` are REPL meta-commands, not SPL text.
- **Implementation Details**:
  - After reading each line in the accumulation phase, check if `line[0] == ':'`.
  - Supported commands:
    - `:quit` / `:exit` — break the REPL loop and return nil.
    - `:help` — print a short help text listing available commands and SPL prompt usage.
    - `:reset` — reset the accumulated buffer, declarations, recordings, and output cursor to initial state (fresh REPL session).
    - Unknown `:<x>` — print "unknown command" to stderr, do NOT accumulate.
  - Lines starting with `:` are NOT accumulated into the block buffer.

### 5.4.5: Implement synthetic skeleton wrapper

- **Goal**: When the first non-empty block is submitted, if it doesn't already parse as valid SPL (missing Title or Acts), prepend a minimal skeleton.
- **Implementation Details**:
  - `makeSkeleton() string`: returns:
    ```
    The REPL Session.
    
    Act I: The REPL Session.
    Scene I: The REPL Session.
    
    ```
  - On first submission, prepend the skeleton to the buffer if `!skeletonBuilt`:
    - Write skeleton string to buffer (if buffer is empty).
    - Set `skeletonBuilt = true`.
  - On subsequent submissions, just append the new text (no skeleton needed).
  - **Auto-wrapping for bare statements**: Before prepending skeleton, check if user input contains keywords `Act`, `Scene`, or `[Enter` (indicating they're writing full SPL). If so, skip skeleton entirely — user is writing standalone SPL.
    - Heuristic: scan the block for `Act I`, `Act`, `Scene`, `[Enter`. If any found, treat as standalone SPL.
    - If block contains dialogue lines like `Romeo:` but no Act/Scene headers, use skeleton.

### 5.4.6: Implement accumulating buffer

- **Goal**: The buffer holds the entire accumulated session SPL source text.
- **Implementation Details**:
  - A `bytes.Buffer` that grows with each successful submission.
  - Before each replay, create a checkpoint: `bufferCheckpoint = buffer.Len()`.
  - On successful replay, advance the checkpoint (implicitly — buffer was modified so `buffer.Len()` is the new baseline).
  - On failed replay, `buffer.Truncate(bufferCheckpoint)`.

### 5.4.7: Implement auto-declaration scanner

- **Goal**: Scan the newly appended text for character names that appear in `[Enter X]`, `[Exit X]`, `X:` dialogue speakers, or `[Exeunt X]` but are not yet in `declaredChars`. For each such name, insert a minimal declaration into the buffer.
- **Implementation Details** (algorithm):
  1. Extract the newly appended text (from `bufferCheckpoint` to end of buffer before auto-declare step).
  2. Scan the new text with regex patterns:
     - `[Enter (A and B)]` → extract "A", "B"
     - `[Exit (X)]` → extract "X"
     - `[Exeunt (A and B)]` → extract "A", "B"
     - `Speaker:` at line start → extract "Speaker"
  3. For each extracted name, check if `declaredChars[lowercaseName]` is true.
  4. For undeclared names:
     - Generate declaration line: `Name, a REPL character.`
     - Append to a new declarations block.
     - Mark as declared: `declaredChars[lowercaseName] = true`.
  5. Before the next replay: insert the declarations block into the buffer at the position after Title and before Act I.
     - Strategy: find the first line starting with `Act I` or `Act` in the buffer. Insert declarations before it.
     - If buffer has skeleton, this is right after the newline after title.
  6. Because the buffer is re-lexed/re-parsed each time, this insertion is safe — the parser will pick up the new declarations.

### 5.4.8: Implement full pipeline replay

- **Goal**: Run the entire SPL pipeline on the accumulated buffer and capture stdout.
- **Context Files**: No new imports needed (already imports lexer, parser, semantic, runtime).
- **Implementation Details**:
  - `runPipeline(buffer []byte, recordedReader io.Reader) (stdout string, execErr error)`:
    1. Create a `bytes.Buffer` named `captureOut`.
    2. Call `lexer.New(string(buffer)).ScanTokens()`. If error → return "", wrapped lex error.
    3. Call `parser.New(tokens).Parse()`. If error → return "", wrapped parse error.
    4. Call `semantic.New("repl", prog).Analyze(prog)`. If `!res.OK()` → return "", formatted semantic errors.
    5. Call `runtime.Execute(prog, res, recordedReader, &captureOut, "repl")`. If error → return "", wrapped runtime error.
    6. Return `captureOut.String()`, nil.
  - Note: `recordedReader` is the custom `io.Reader` that replays recorded stdin then prompts for new input.

### 5.4.9: Implement recorded-stdin `io.Reader`

- **Goal**: A custom `io.Reader` that serves recorded bytes first, then prompts the user for new input.
- **Implementation Details**:
  - Type `recordedReader` struct:
    - `recorded []byte` — the recorded input bytes
    - `cursor int` — current read position within `recorded`
    - `live io.Reader` — `os.Stdin` for prompting
    - `prompted bool` — has prompted for this read?
  - `Read(p []byte) (n int, err error)`:
    1. If `cursor < len(recorded)`: serve bytes from `recorded[cursor:]` up to `len(p)`. Advance cursor. Return served count.
    2. If exhausted, switch to live mode:
       - Print `input> ` prompt to `os.Stderr` (first time only).
       - Read from `live` (os.Stdin) into `p`.
       - Append the read bytes to `recorded` (growing the recording).
       - Advance `cursor`.
       - Return read count.
  - After each pipeline run (whether success or failure), the `recorded` slice has grown with any new inputs the user typed.
  - On rollback: restore `recordedCursor` to checkpoint value, truncate `recorded` to that length.

### 5.4.10: Implement output slicing (delta display)

- **Goal**: Display only the NEW output produced by the latest replay.
- **Implementation Details**:
  - `sliceOutput(fullOutput string, lastLen int) string`:
    - If `len(fullOutput) <= lastLen`: return `""` (no new output).
    - Return `fullOutput[lastLen:]`.
  - After a successful replay:
    - Compute `delta := sliceOutput(capturedOut.String(), lastOutputLen)`.
    - Print `delta` to `cmd.OutOrStdout()`.
    - Update `lastOutputLen = len(capturedOut.String())`.
  - Rationale: Because stdin replay is deterministic and the buffer only grows, the output is monotonic — earlier outputs are byte-prefixes of later outputs.

### 5.4.11: Implement buffer rollback on failure

- **Goal**: On any pipeline failure, undo the buffer append and input recording to the last successful state.
- **Implementation Details**:
  - Before each replay attempt (after appending new text to buffer):
    - Save `bufferCheckpoint = buffer.Len()`
    - Save `recordedCheckpoint = len(recorded)` (the length of the recorded inputs slice).
  - After successful replay:
    - Discard checkpoints (they advance to current state).
  - After failed replay:
    - `buffer.Truncate(bufferCheckpoint)` — remove the newly appended text.
    - `recorded = recorded[:recordedCheckpoint]` — remove any newly recorded stdin bytes.
    - `recordedCursor = recordedCheckpoint`.
    - Print the error message to `os.Stderr`.
    - Return to `spl>` prompt without changing `lastOutputLen`, `declaredChars`, or `skeletonBuilt` (those are permanent).
  - Edge case: first submission fails because user typed invalid SPL. Buffer is restored to empty, they can try again.

### 5.4.12: Wire all pieces in `replCmd.RunE`

- **Goal**: The `RunE` closure assembles all the pieces.
- **Implementation Details** (algorithm):
  ```
  RunE:
    initialize REPL state struct
    set up SIGINT handler goroutine
    enter replLoop:
      for each block from input loop:
        if block is a meta-command (:quit, :reset, etc.): handle it
        if block is empty: continue
        
        // Phase A: Append to buffer
        checkpoint buffer and recorded cursor
        if !skeletonBuilt and block looks like bare dialogue:
          prepend skeleton to buffer
          skeletonBuilt = true
        if block references new characters:
          generate declarations and insert before Act I
        append block to buffer
        
        // Phase B: Replay pipeline
        result, err := runPipeline(buffer.Bytes(), recordedReader)
        if err != nil:
          rollback buffer and recorded cursor
          print error to stderr
          continue
        
        // Phase C: Show new output
        delta := fullOutput[lastOutputLen:]
        print delta to stdout
        lastOutputLen = len(fullOutput)
        
        // Phase D: Advance checkpoints
        discard checkpoints (they implicitly advance)
  ```

    - D5: Auto-declaration scans for character names in Enter/Exit/Exeunt/dialogue speakers.
    - D6: Output slicing via byte-length prefix, not line-by-line diff.
    - D7: `os.Exit(1)` eliminated from command handlers — all errors flow through Cobra's `RunE` return.
  - Add a "Trade-offs" subsection:
    - O(n²) replay complexity (negligible at human scale).
    - Infinite loops incompatible with replay model (out of scope).
    - No stdin prompt customization beyond `input>` prefix.

## Appendix B: Error Taxonomy for CLI Operations

| Error Code (informal) | Description | Where Raised | User Output |
|---|---|---|---|
| `file not found` | Input file doesn't exist | `os.ReadFile` in tokens/ast/run | `cannot read file "X": ...` |
| L001-L002 | Lexer errors | `lexer.ScanTokens()` | `error[L001]: ...` to stderr |
| S001-S018 | Parser errors | `parser.Parse()` | `error[S001]: ...` to stderr |
| M001-M008 | Semantic errors | `semantic.Analyze()` | `error[M001]: ...` aggregated to stderr |
| R001-R004 | Runtime errors | `runtime.Execute()` | `error[R001]: ...` to stderr |
| — | REPL pipeline failure | `replCmd.RunE` | Error printed inline at `spl>` prompt, buffer rolled back |
